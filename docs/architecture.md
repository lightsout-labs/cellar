# Architecture

Status: Approved

How Cellar is built. What it must do is in
[requirements.md](requirements.md). Reasons for the decisions that are costly
to reverse are in the ADRs under `docs/adr/`.

## Overview

Cellar is a static single-page application in two parts. The **engine** is
plain TypeScript with no DOM dependency: it owns the workbook, executes
every edit as a command, recalculates formulas, and reads and writes files.
The **app** is the browser side: a canvas that draws the grid, React
components for everything around it (ribbon, formula bar, sheet tabs,
dialogs), and one platform module that is the only code allowed to touch
files, storage, the clipboard and printing. When the user types in a cell,
the grid passes the text to the app, the app sends a `setCell` command to
the workbook, the workbook parses the input, stores it, records the inverse
for undo, marks dependent cells dirty and notifies its listeners; the grid
repaints the visible cells, reading each one from the workbook (which
calculates a dirty cell when it is read), and the app asks the platform to
save the changed sheet to browser storage a moment later.

## Stack

| Concern | Choice | Why |
|---|---|---|
| Language | TypeScript, strict mode | Constraint. |
| Build and dev server | Vite | Static output for GitHub Pages; sub-path via `base` (R49). |
| UI around the grid | React | The ribbon, menus and dialogs are many stateful controls; see [ADR 0002](adr/0002-canvas-grid-react-chrome.md). |
| Grid | One HTML canvas, drawn by our own code | Only a virtualized canvas meets R45; see [ADR 0002](adr/0002-canvas-grid-react-chrome.md). |
| Menus, dialogs, tooltips, tabs | Radix UI primitives, unstyled | Correct focus, keyboard and dismissal behavior for R38 and R44 without writing it; all styling stays ours (R43). |
| Styling | CSS Modules and CSS custom properties | Themes are two sets of variables (R42); no styling library needed. |
| Icons | Lucide | The single consistent icon set of R43. |
| Fonts | The system UI font stack | Works offline (R35) and loads nothing. |
| Formula engine and workbook model | Our own | See [ADR 0001](adr/0001-own-formula-engine.md). |
| Number formats and input recognition | `numfmt` | Implements Excel format codes and value parsing (R4, R18). |
| `.xlsx` | ExcelJS | See [ADR 0003](adr/0003-exceljs-for-xlsx.md). |
| `.csv` | Our own reader and writer | About a hundred lines; no dependency justified (R32). |
| Threads | Main thread only, recalculation on demand | See [ADR 0004](adr/0004-main-thread-lazy-recalculation.md). |
| Browser storage | IndexedDB, used directly | Holds large workbooks; the few calls needed do not justify a wrapper (R33). |
| Offline | A service worker generated by `vite-plugin-pwa`, with no web app manifest | Precaches the build output (R35); installable PWA packaging is out of scope. |
| Translation | Our own `t(key)` over two dictionaries | Two languages and plain strings need no library (R41). |
| Unit tests | Vitest, Node environment for the engine | Running the engine tests in Node demonstrates R50. |
| End-to-end tests | Playwright on Chromium, Firefox and WebKit | The supported browsers (Constraints). |
| Lint and format | ESLint, Prettier, `tsc --noEmit` | ESLint also enforces the module boundaries below. |
| Package manager and runtime | npm and the current Node.js LTS, pinned in `.nvmrc` | The default; nothing needs more. |
| Hosting | GitHub Pages, deployed by GitHub Actions | Constraint (R49). |

There is no state management library: the workbook is the store, and React
reads it with `useSyncExternalStore`.

## Modules

Each module has a small interface and hides substantial behavior. Tests go
through the interface only. Every module, layer, and dependency is here
because a requirement needs it.

| Module | Interface | Hides |
|---|---|---|
| `engine/workbook` | `execute(command)`, `undo()`, `redo()`, `cell(sheet, row, col)` (value, formula, display text, style, note, link), queries (`find`, `aggregate`, sheet and name lists, layout), `subscribe(listener)`, `toSnapshot()`, `fromSnapshot()` | Column-oriented cell storage; the dependency graph and on-demand recalculation; circular-reference detection; rewriting references when rows, columns and sheets move; inverse patches for undo; fill series; sort; filters; merges; data validation; conditional format evaluation; named ranges (R1, R5, R6, R8–R10, R14, R15, R19–R27). |
| `engine/formula` | `parse(text)`, `print(ast)`, `evaluate(ast, context)`, `shift(ast, move)`, `functions` (name, argument hints) | Tokenizer and parser; operators and coercion rules; the error values; the library of at least 150 functions (R11–R13, R16). Used only by `engine/workbook`, plus `functions` by the autocomplete. |
| `engine/format` | `formatValue(value, code)`, `parseInput(text)` | Excel format codes, date serial numbers, and recognition of typed numbers, dates, times, percentages and booleans, on top of `numfmt` (R4, R18). |
| `engine/io` | `readXlsx(bytes)`, `writeXlsx(snapshot)`, `readCsv(text)`, `writeCsv(snapshot, sheet)` | The mapping between a workbook snapshot and ExcelJS; the list of dropped features reported on import; CSV quoting (R30–R32). |
| `app/platform` | The `Platform` interface: `openFile()`, `saveFile(name, bytes)`, `workbooks` (list, load, save, rename, delete), `preferences` (get, set), `clipboard` (read, write), `print(document)`; and `webPlatform`, its one implementation | File inputs and downloads; the IndexedDB schema; clipboard events and the asynchronous clipboard API with their browser differences; the print frame (R33, R34, R51). |
| `app/grid` | `<Grid workbook view />` and the `View` it edits (active sheet, selection, scroll position, zoom, edit state) | Canvas drawing and virtualization; frozen panes; hit testing; text measurement and caching; selection, resize, fill-handle and reference-picking gestures; the in-cell editor; keyboard navigation (R2, R3, R8, R9, R16, R21, R45). |
| `app/ui` | `<App platform />` | The start screen, ribbon, formula bar and name box, sheet tabs, status bar, context menus, dialogs and side panels; shortcuts; translation dictionaries; themes; autosave timing; building the printable document (R34, R36–R44). |

Boundaries, enforced by the build so that R50 and R51 cannot erode:

- `src/engine` compiles with its own `tsconfig` that excludes the DOM
  library, and ESLint forbids it from importing `src/app`.
- ESLint forbids `indexedDB`, `localStorage`, `navigator.clipboard`,
  `window.print`, file inputs and download links everywhere except
  `src/app/platform/web`. A desktop shell such as Tauri or Electron would
  add a second implementation of `Platform` beside it and reuse everything
  else.

Decisions that are cheap to reverse, with their reasons:

- **Every edit is a command.** The workbook returns the inverse of each
  command it executes, so undo covers every change by construction (R5)
  rather than feature by feature.
- **Cells are stored by column**, as arrays of values and of style
  identifiers, with formulas in a sparse map. Ten million populated cells
  (R45) do not fit in memory as one object each.
- **Dates are Excel serial numbers** with a date format, as in Excel, so
  date arithmetic and `.xlsx` round trips need no conversion.
- **Number and date formats do not change with the interface language.**
  R41 covers the interface only; one behavior keeps files and tests the
  same in both languages. Function names stay in English in both languages,
  as they are in `.xlsx` files.
- **Files are opened with a file input and saved as a download.** It works
  in all four browsers; the File System Access API does not.
- **Cell fonts are a fixed list of fonts present on all three desktop
  systems**, with fallbacks, so that nothing is downloaded.
- **Printing builds a plain HTML table** of the sheet or selection with
  print CSS for page size, orientation and margins, and rows that do not
  break across pages (R36). The canvas itself cannot be paginated.

## Data

A workbook **snapshot** is a versioned, JSON-compatible object: workbook
properties (name, sheet order, named ranges, the table of distinct styles)
and, for each sheet, its columns of values, style identifiers, formulas, row
heights and column widths, merges, frozen panes, filters, validation rules,
conditional formats, notes and hyperlinks. It is the only form in which a
workbook leaves the engine.

- **Browser storage**: an IndexedDB database named `cellar` with two object
  stores. `workbooks` holds one record for each workbook (identifier, name,
  modification time, workbook properties). `sheets` holds one record for
  each sheet, keyed by workbook and sheet identifier, so that autosave
  rewrites only the sheets that changed. Autosave runs half a second after
  the last change and when the page is hidden. A save cannot be started
  while the page unloads: browsers discard an IndexedDB transaction that
  begins then.
- **Preferences** (language, theme): through `Platform.preferences`, stored
  in `localStorage` by the web implementation.
- **Files**: `.xlsx` and `.csv`, converted to and from a snapshot by
  `engine/io`. Undo history is not stored.

## Repository layout

```
src/engine/value.ts      The value types shared by the engine modules
src/engine/workbook/     Workbook model, commands, recalculation, undo
src/engine/formula/      Parser, evaluator, function library
src/engine/format/       Number formats and input recognition
src/engine/io/           XLSX and CSV
src/app/platform/        Platform interface
src/app/platform/web/    The web implementation
src/app/grid/            Canvas grid and the view state
src/app/ui/              React shell, dictionaries, themes
src/main.tsx             Entry point: creates the web platform, mounts App
tests/e2e/               Playwright tests
tests/boundaries.test.ts Checks that lint enforces the module boundaries
tests/fixtures/          Sample .xlsx and .csv files
scripts/check-docs.py    Document checker, copied from nightshift
docs/                    Requirements, architecture, ADRs, backlog
.github/workflows/       CI and deployment
```

Unit tests sit beside the code they test, as `*.test.ts`. In `src/app`, code
that touches the DOM is in `.tsx` files or in `src/app/platform/web` and is
covered by the end-to-end tests; every other `.ts` file there has no DOM, is
unit tested, and counts toward the coverage floor.

## Make targets

| Target | Contents |
|---|---|
| `make check` | `prettier --check`, `eslint`, `tsc --noEmit` for both the engine and the app configuration, `vitest run --coverage` with a floor of 90% of lines in `src/engine` and in the parts of `src/app` that have no DOM, `scripts/check-docs.py` |
| `make e2e` | Builds the production bundle, serves it with `vite preview` under `/cellar/`, and runs the Playwright tests against it |

CI runs both on every pull request as the required checks `check` and `e2e`.

## Testing

| Level | Covers | How |
|---|---|---|
| Unit | The engine through its four interfaces: every command and its undo, every function against results taken from Excel's documentation, reference rewriting, recalculation and its time limit (R46), number formats, XLSX and CSV round trips and the 10 MB open time (R47) | Vitest in the Node environment, with no DOM available |
| Unit | App logic that needs no browser: translation completeness for both languages, shortcut tables, the printable document | Vitest |
| End to end | Each slice's user flow in the built app: keyboard and mouse on the grid, the ribbon, menus and dialogs, storage across reloads, file open and save, both themes and languages, offline use | Playwright on Chromium, Firefox and WebKit |
| End to end, Chromium only | The system clipboard (R7), and scrolling speed (R45), measured as the time to draw each frame while scrolling a sheet of 100,000 by 100 populated cells | Playwright |

Two requirements cannot be fully checked by automated tests and are checked
by the human at release acceptance: that files saved by Cellar open in
Microsoft Excel itself (R30), and the 60 frames per second on a mid-range
laptop (R45). The automated tests cover them as far as they can: files in
`tests/fixtures` that were saved by Excel, round trips through the writer
and reader, and a frame-time budget with headroom for CI machines.

## Deployment

The app runs at `https://lightsout-labs.github.io/cellar/`. A GitHub Actions
workflow runs on every push to `main`: it builds the production bundle with
the base path `/cellar/`, publishes it with the GitHub Pages actions, and
then runs one Playwright smoke test against the live address, which loads
the app, enters a formula and checks the result. It is the end-to-end test
tagged `@smoke`, run with `CELLAR_URL` set to the live address. A failed smoke test fails
the workflow. A release is verified by that smoke test and by the human's
acceptance of the deployed app.
